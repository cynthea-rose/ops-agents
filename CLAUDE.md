## Project
ops-agents: a multi-agent operations assistant. A coordinator agent splits plain-English requests into tasks for specialist agents (inventory, logistics, finance). All data acccess goes through one MCP server with per-agent permissions and an audit log. I'm building this to learn these technologies properly, so I need to understandd every line that goes in.

## Current phase: Phase 1 (MCP server)
- Seed script that builds a SQLite database (orders, shipments, inventory, suppliers) with a small, relaistic dataset
- MCP server exposing 3-4 read-on;y tools over it, using the official Python MCP SDK
- Verify it works with the MCP Inspector

## Stack and commands
- Python 3.12, managed with uv
- Add dependencies with 'uv add <package>. Never use 'pip inatall'
- Run anything with 'uv run <command>'
- src layout: package code lives in 'src/ops_agents/' , tests in 'tests/'

## Rules
- Secrets live only in '.env' (git-ignored). Never print, log or commit the API key. When adding a new variable, also add it to '.env.example'
- The SQLite database is generated by the seed script and is never committed
- Agents never query the database directly. All data access goes through MCP tools
- Permissions are enforced in code, not in prompts
- Tool outputs are structured (typed), not free text
